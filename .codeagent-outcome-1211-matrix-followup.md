## Diagnostics design

Shared MIME validation records the loop-owned `attachmentIndex` and one closed reason: `mime_type_not_string`, `mime_type_too_long`, `mime_type_whitespace`, `mime_type_control_characters`, or `mime_type_invalid_unicode`. Only `mime_type_too_long` records `maxMimeTypeBytes=256`. Ill-formed UTF-16 content records only its attachment index and `reason=invalid_unicode`.

The continuation redactor accepts exact anchored MIME and content shapes, checks the MIME maximum against the compiled constant, and reconstructs output from those allowlisted fields. It never forwards the attachment name, content, MIME value, path, mount destination, receipt identifier, or arbitrary raw error text.

Mount parsing now returns a closed invalid reason: `invalid_type`, `too_long`, or `unsupported_characters`. The `continue_delegate` reader handles non-string values before parsing, projects `too_long` with the compiled `maxMountPathBytes=1024`, and projects unsupported characters without echoing the mount.

## Complete validation-matrix audit

- Collection admission: absent/empty attachments, disabled attachments, and maximum file count remain structurally handled; only the active `maxFiles` value is projected for count overflow.
- Reader boundary: non-array collections, malformed members, non-string name/content/MIME fields, and unsupported encodings are rejected with safe field/index descriptions before shared decoding.
- MIME: non-string, too-long, leading/trailing whitespace, control-character, and invalid-Unicode cases now have closed reasons and an attachment index; only too-long includes the compiled MIME limit.
- Name: invalid Unicode, whitespace, forbidden/control characters, overlong UTF-8 basename, aliases, device names, and duplicate normalized names remain name-redacted. The continuation projection retains only the attachment index, plus measured/canonical basename limits for the exact overlong shape.
- Content and bytes: invalid Unicode, malformed/oversized base64, UTF-8 per-file overflow, and aggregate overflow retain the failing attachment index. File and aggregate diagnostics reconstruct only the applicable active numeric limit.
- ACP image MIME rejection is outside `continue_delegate` admission and remains unchanged.
- Mount: absent, valid, invalid-type, overlong, and unsupported-character states are distinct. Other mount consumers inspect only `status`, so the added invalid reason does not alter their acceptance behavior.
- Materialization: ordinary `sessions_spawn` typed diagnostics and continuation's structural-only materialization failure remain unchanged.
