Fixes #125333

## What Problem This Solves

#123065 added an "unavailable context" barrier that only applies when `assistant.api === "cli"`. For every other provider the cumulative assistant usage was still the first candidate the "latest call" selector picked, and the separate transcript-derived memory-flush write path re-derived usage from raw transcript `message.usage` with no window check and no downward correction — an unguarded ratchet that could only grow `totalTokens`, occasionally past the model's actual context window.

## Root cause

1. `resolveLatestCallUsage` (`src/agents/embedded-agent-runner/run/helpers.ts`) is called from `attempt-normalization.ts` with candidates ordered `[currentAttemptAssistantUsage, promptCacheLastCallUsage]`. `.find(hasNonzeroUsage)` returns the first nonzero candidate, and for non-CLI providers `currentAttemptAssistantUsage` is (almost) always nonzero, so `attempt.promptCache.lastCallUsage` — explicitly documented as "usage from the most recent API call, not accumulated retry/tool-loop totals" (`src/context-engine/types.ts`) — was never actually consulted.
2. `deriveTranscriptUsageSnapshot` (`src/auto-reply/reply/agent-runner-memory.ts`) passes whatever raw usage it finds in the last nonzero transcript event straight into `deriveContextPromptTokens` as `lastCallUsage`, with no bound. The writer only persists a value when it's fresh-missing or strictly larger than the persisted value (`transcriptPromptTokens > persistedPromptTokens`), so an inflated snapshot can never be corrected downward, and — per the issue's measurement — this occasionally exceeds the model's own context window, which is physically impossible for a genuine prompt-token snapshot.

## Fix

1. **`src/agents/embedded-agent-runner/run/attempt-normalization.ts`** — reorder the selector candidates to `[promptCacheLastCallUsage, currentAttemptAssistantUsage]`, so the authoritative final-call context fact is preferred for every provider, not just `cli`. `currentAttemptAssistantUsage` remains the fallback for attempts where no last-call snapshot was captured.
2. **`src/agents/usage.ts`** — `deriveContextPromptTokens` gains an optional `contextWindowTokens` bound. A derived prompt-token count larger than the window is rejected (`undefined`) rather than trusted, since it can't be a genuine single-call context snapshot for that window. This is the single choke point both the live-run and transcript-persistence write paths already pass through, so the invariant is enforced once instead of re-guarded per call site.
3. **`src/auto-reply/reply/agent-runner-memory.ts`** — thread `contextWindowTokens` through `deriveTranscriptUsageSnapshot` → `readSqliteSessionLogSnapshot` → `readSessionLogSnapshot`, and into both callers (`runMemoryFlushIfNeeded`'s transcript read and `estimatePromptTokensFromSessionTranscript` used by `runPreflightCompactionIfNeeded`). When the transcript-derived snapshot is rejected as out-of-window, existing fallback logic (`hasUsableProviderPromptUsage` → full-message prompt-token estimation) takes over instead of persisting/ratcheting on the impossible value.
4. **`src/auto-reply/reply/agent-runner-memory.ts`** (review follow-up) — `runMemoryFlushIfNeeded`'s `onAgentEvent` handler treated any `stream: "compaction"` event with `phase: "end"` as a completed compaction, even though that event also fires when compaction is aborted or fails (`completed: false`). That incremented the persisted `compactionCount` and rotated `sessionId` for a non-rewrite, invalidating fresh token accounting. Gated on `evt.data.completed === true` so only a successful rewrite counts.

## Scope note

This does not yet persist `promptCache.lastCallUsage` into the transcript log itself (the issue notes 0/59 recent events carried it in a sampled session). That would let the transcript-derived path distinguish a genuine last-call snapshot from cumulative usage even when it's *within* the window (the sub-window inflation case the issue explicitly says consumer-side clamping can't catch). The window-bound check here removes the worst failure mode (compaction firing on a physically impossible number) and fixes the live-run selector bug outright, but closing the remaining sub-window gap needs new transcript-persistence plumbing, which felt like a separate, larger change from this fix.
