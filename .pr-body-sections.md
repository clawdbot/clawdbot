## Scope correction (replaces the coverage claim in "User Impact")

**Coverage, stated precisely:** this repairs `AGENTS.md` delivery for remapped-sandbox turns
**that carry OpenClaw workspace context** — i.e. runs whose bootstrap context mode is not
`lightweight`.

Lightweight runs (cron, heartbeat) are out of scope by design, and the PR does not change them.
On those runs `AGENTS.md` is unavailable through _either_ path, for three independent reasons:

1. `shouldInjectCodexOpenClawPromptContext` returns false for lightweight cron
   (`extensions/codex/src/app-server/attempt-context.ts:570-576`).
2. More fundamentally, `applyContextModeFilter` returns `[]` for any lightweight run
   (`src/agents/bootstrap-files.ts:151-163`), so no `AGENTS.md` object is ever loaded —
   the fallback has nothing to inject even where the gate passes (lightweight heartbeat).
3. Codex's native loader is switched off for those threads via `project_doc_max_bytes: 0`
   (`extensions/codex/src/app-server/thread-requests.ts:52-54`).

That is the deliberate contract pinned by
`extensions/codex/src/app-server/run-attempt.test.ts` ("keeps lightweight cron Codex turns out of
OpenClaw bootstrap context"), which also asserts the user command stays byte-for-byte.
This PR adds one assertion to that test so the narrowing is pinned on the turn-scoped carrier as
well, not just on `thread/start`.

### Note on the review finding

The finding assumed the turn-scoped carrier is unavailable on lightweight cron. It is in fact
delivered: `preserveNativeTurnSettings` is `usesSupervisionConnection`
(`extensions/codex/src/app-server/run-attempt-turn-request.ts:117`), which is false for cron —
it is only true when adopting a native Codex thread under `codex.supervision.enabled`
(`run-attempt-connection.ts:182-186`, `session-catalog.ts:1028`) — and
`resolveCodexAppServerRequestModelSelection` always returns an object
(`thread-model-selection.ts:82`). The cron branch actively populates it
(`turn-params.ts:135-137`).

Injecting there would still be a no-op because of (2) above. Making it work would mean re-reading a
file that lightweight mode deliberately drops and re-inflating a turn that the existing test pins as
context-free — a product-policy reversal, not a bug fix. Hence: narrowed coverage rather than
extended injection.

## Upstream Codex contract (discharges the "could not be inspected" blocker)

Inspected directly against the pinned harness version: `openai/codex` tag **`rust-v0.147.0`**,
commit **`be6e8eac029b183056b7e4402879f15d2c85f61b`**, matching
`extensions/codex/package.json` `"@openai/codex": "0.147.0"`.

**Native project-doc resolution walks up from the thread `cwd`:**

- `codex-rs/core/src/agents_md.rs:154` `agents_md_paths()` — `:159` seeds from `cwd`, `:184-201`
  walks `cursor.parent()` up to the nearest project-root marker.
- Accepted basenames: `AGENTS.override.md` (`:39`), `AGENTS.md` (`:37`), then configured fallbacks
  (`:230-244`).

**It resolves on the host, never through the sandboxed filesystem backend:**

- `agents_md.rs:113` `fs.read_file(&p, /*sandbox*/ None)`, `:211` `get_metadata(..., /*sandbox*/ None)`,
  `:181` same for the marker probe.
- `codex-rs/exec-server/src/local_file_system.rs:80-92` — `None` dispatches to `self.unsandboxed`.

This is the exact mechanism this PR repairs: OpenClaw starts the thread with the **container**
workdir, while resolution runs unsandboxed in the app-server process, so the loader walks a path
that does not exist there. "Remapped" refers to OpenClaw's execution cwd, not to any path
translation inside Codex — Codex performs none for project docs.

**`project_doc_max_bytes: 0` is a complete disable, not a truncation:**

- `agents_md.rs:94-98` returns `Ok(None)` before any discovery or filesystem access.
- Upstream test: `codex-rs/core/src/agents_md_tests.rs:1020-1031` `zero_byte_limit_disables_docs`.

**Turn-scoped developer-instruction carrier:**

- `codex-rs/app-server-protocol/src/protocol/v2/turn.rs:148-155` `collaboration_mode` on
  `TurnStartParams`; rendered to the model as a `developer`-role `<collaboration_mode>` fragment at
  `codex-rs/core/src/context/world_state/collaboration_mode.rs:20-42,100-115`.

**Correction worth recording:** omitting `collaborationMode` does _not_ clear developer
instructions — `codex-rs/core/src/codex_thread.rs:439-445` falls back to the session's sticky
collaboration mode, and `with_updates(..., developer_instructions: None)` means "keep current"
(`codex-rs/protocol/src/config_types.rs:700,713-714`). The supervised-turn note in this PR is about
OpenClaw not _sending_ the turn-scoped payload; it should not be read as Codex dropping
instructions.
