# Patterns

## Do

- Use truncateUtf16Safe(text, N) from @openclaw/normalization-core/utf16-slice (server) / openclaw/plugin-sdk/text-utility-runtime (extensions) instead of text.slice(0, N) when bounding any runtime string that may contain emoji or other non-BMP Unicode
- Test surrogate safety at the exact boundary using `${"x".repeat(N-1)}😀tail` and assert truncated parts equal "x".repeat(N-1) (avoids counting the 2-code-unit emoji as 1)
- Normalize whitespace then truncate with fallback: (rawReason.replaceAll(/\s+/gu,' ').trim() || fallbackReason) wrapped by truncateUtf16Safe(..., 300) as in src/agents/workspace.ts:1216
- Guard runtime-metadata inheritance on exact target identity (targetSessionKey + targetKind equality) before spreading previous.metadata; separates conversation transport fields (deliveryTo/deliveryThreadId, idleTimeoutMs) that may carry forward from target-owned fields (pluginBindingOwner/pluginId/pluginRoot/agentId/boundBy/opaque/label) — implemented in all 5 binding managers
- Thread explicit agentId through status pipeline (BuildStatusTextParams.agentId -> resolveSessionAgentId -> buildControlledSubagentRunsReadContext/listControlledSubagentRuns) instead of inferring default agent for bare `global` session key shared by multiple agents
- Filter subagent status with liveness helpers isLiveUnendedSubagentRun/hasSubagentRunEnded plus pendingDescendantsForRun rather than checking only endedAt existence — prevents stale 3h unended runs counting as active
- Use it.each([false,true]) replace-parameterized binding tests asserting field-by-field leakage (for loop over pluginBindingOwner/pluginId/pluginRoot/agentId/boundBy/opaque) and persist+recreate roundtrip for Telegram/imessage managers
- Centralize string coercion via normalizeOptionalString from @openclaw/normalization-core/string-coerce instead of manual `typeof x==='string' && x.trim() ? x.trim() : existing` branches
- Store accepted Control UI input in per-agent SQLite (session_pending_inputs) before Gateway ACK and finish with cancelled/interrupted disposition via finishPendingInput() in src/gateway/server-methods/chat-send-handler.ts:admitChatSend – separates durability from execution authority.
- Use same-version additive migration pattern: add nullable session_pending_inputs.consumed_event_id TEXT without bumping user_version, converge via ensurePendingInputConsumptionColumn() in src/state/openclaw-agent-db-session-migrations.ts:ensureSessionAdditiveColumns, hasPendingInputConsumptionColumnMigration() check in assertAgentDatabaseIntegrityBeforeMutation, and cached presentDatabases/completeDatabases WeakSets in src/state/openclaw-agent-pending-inputs-schema.ts.
- Bound browser reconciliation independently of transcript length via CHAT_INPUT_CONSUMPTION_MAX_RUN_IDS=50 and CHAT_INPUT_RUN_ID_MAX_CHARS=256 in packages/gateway-protocol/src/schema/chat-history-constants.ts and ChatInputConsumptionsSchema maxItems, validated in logs-chat.ts and GatewayModels.swift CodingKeys.
- Avoid double approval hooks by skipping before_message_write when getPendingInputMessage() exists: skipUserWriteHook in src/agents/session-tool-result-guard-wrapper.ts and conditional beforeMessageWrite in user-turn-transcript.ts bind path.
- Isolate persistence vs execution ownership with WeakMap receiptOwners and withSessionPendingInputPersistence()/runWithSessionPendingInputPersistence() plus runWithSessionPendingInput() and withRuntimeUserTurnTranscriptRecorder() for steered messages in src/sessions/user-turn-transcript-runtime-context.ts.
- Bind collected aggregate to exact source closures not persisted identifiers via bindSessionPendingInputSources() validating single session/database, disjoint idempotencyKey, and atomic consumed_event_id write; sources persist until session window deleted so rewriting transcript cannot make old input runnable again.
- Render collected prompts from approved PersistedUserTurnMessage via extractTextFromChatContent(message.content) not queue prompt/transcriptPrompt in src/auto-reply/reply/queue/drain.ts:resolveCollectedSourceText and src/auto-reply/reply/queue/enqueue.ts summarize, preventing pre-approval text from resurfacing after redaction.
- Scope consumption receipts to currently selected physical session (not archived history) via sessionId===entry.sessionId guard in src/gateway/server-methods/chat-history-handler.ts and pane-scoped readChatInputRunIds() (pending projection + queue sendRunId, deduped sorted sliced) in ui/src/pages/chat/chat-pending-inputs.ts with requestKeyPrefix including inputRunIds.
- Preserve restart vs RPC abort disposition on queued turns by mapping stopReason===restart to createAgentRunRestartAbortError() and checking isAgentRunRestartAbortReason() in src/gateway/chat-queued-turns.ts and chat-send-handler cleanup, so restart-interrupted inputs remain retryable.
- Use transactional collect semantics: In collect mode, appending the combined turn and marking its source inputs consumed happen in one transaction (docs/concepts/queue.md), implemented via recorder.markRuntimePersisted(message, anchor) with anchor in session-tool-result-guard-wrapper.ts.
- Use per-command startup policy in src/cli/command-catalog.ts via policy: { configGuard: 'skip', loadPlugins: 'never', networkProxy: 'bypass' } to make teardown commands independent of config validity
- Group all recovery/teardown commands (gateway stop, gateway diagnostics export, gateway stability, hooks check, memory search/status) into the same minimal-startup tier and enforce via an explicit allowlist test in src/cli/command-startup-policy.test.ts
- Bypass network proxy for local-only lifecycle commands to avoid external dependencies during stop/uninstall

## Avoid

- Bounding dynamic text with String.prototype.slice/substring on UTF-16 code units, which splits surrogate pairs and produces malformed Unicode / isolated surrogates / � replacement characters
- Interpolating unbounded profileId or Error.message directly into fixed-length fields (A2A status message parts, Cloud worker displayName, [UNREADABLE: ...] reason) without safe truncation
- Unconditionally spreading `...existingValue?.metadata` / `...existing?.metadata` on rebinding regardless of new targetSessionKey/targetKind, letting a new session inherit previous plugin owner/agent/label
- Resolving global-session owner via resolveDefaultAgentId in buildStatusReplyParts instead of caller-provided agentId, leaking other agents' subagents into status/ /subagents list/info/log
- Counting any run without endedAt as active without liveness/age check and without distinguishing done (hasSubagentRunEnded && pendingDescendants===0)
- Ad-hoc inline trim checks for agentId/label/boundBy duplicated per manager instead of reusing normalizeOptionalString
- Avoid relying on in-memory followup queue across restarts – docs/gateway/restart-recovery.md now states in-memory queue is not replayed; accepted inputs survive as SQLite pending inputs but require explicit resend and do not auto-run.
- Avoid automatically re-executing unconsumed durable input after restart – separates input preservation from execution permissions; old queue and authority are discarded, only text survives as interrupted (docs/concepts/queue.md, restart-recovery.md, control-ui.md).
- Avoid re-running plugin before_message_write approval hook on already-approved source bytes – now skipped via skipUserWriteHook when recorder.getPendingInputMessage() exists, only core redaction/visibility runs on consume.
- Avoid restoring pre-approval display text when combining queued messages – collect now resolves via persisted approved message content, not queue.prompt/summaryLine projection.
- Avoid creating a second durable queue row for the collected aggregate – bindSessionPendingInputSources uses existing source closures and a single consumed_event_id update instead of inserting another pending input.
- Avoid carrying unstaged input past approval via stale delivery-context key – now includes Boolean(getPendingInputMessage()) in resolveFollowupDeliveryContextKey() so approved sources are not mixed with unstaged input.
- Avoid unbounded or cross-pane consumption queries – now bounded to 50 runIds, max 256 chars, unique, and per-pane via readChatInputRunIds(); history requests coalesce only when inputRunIds slice is identical.
- Avoid misclassifying restart aborts as generic errors – now creates distinct restart abort reason via createAgentRunRestartAbortError() so queued-turn signals retain retryable vs tombstone semantics.
- Requiring full configGuard validation and plugin initialization for a `stop` command — couples availability of the cleanup path to the validity of the state it needs to clean up, breaking forward-compatibility when schemas evolve
- Inconsistent startup tiering where peer recovery commands already use skip/never/bypass but `gateway stop` remains at only networkProxy: bypass, leaving a single fragile entry point
